# Цензурки: роадмап пополнения словарей

Это рабочая память для агентов. Сюда записывают, куда двигаться, что уже
сделано и что отвергнуто. Архитектура описана в
[censorly-matching-architecture.md](censorly-matching-architecture.md),
правила работы — в [agents/censorly-matching.md](../agents/censorly-matching.md).

## Метрики и цели (с 2026-11-09)

Набор метрик считает `python -m games.puzzles.censorly.offline.tools.metrics`
(~2.5 мин); его строки `METRICS …` идут в журнал. Код и определения лежат в
`offline/metrics.py`.

**Покрытие** — доля русских токенов статей, у которых есть игровой корень
(корень в банке, дефисная структура или alias). Считается на основном
корпусе (996 статей) и на отложенной выборке (497 других статей; ни одна
очередь её не читает). Разбивка по группам слов:

* `common` — слова, известные pymorphy, кроме имён собственных. **Главная
  цель покрытия: ≥95% на отложенной выборке.**
* `proper` — имена, фамилии, топонимы, организации (теги pymorphy). Им корень
  нужен только для связей с прилагательными, а их трек P даёт парами, которых
  покрытие не видит. Цели нет, только наблюдение.
* `unknown` — кириллица вне словаря pymorphy, почти вся она — имена.
* `short` — однобуквенные токены и сокращения.
* `all` — всё вместе. Прежняя цель «≥90% `all`» снята: две трети остатка —
  имена (на 2026-11-09 `proper`+`unknown` ≈ 12% токенов при покрытии ~25%).
  `all` считает только кириллицу и потому на ~0.4 п.п. ниже старого
  `rooted_russian_tokens`, который держал в числителе цифры с корнем.

**Правильность** — какая доля открытий, которые встречает игрок, верна.
Покрытие её не видит: неверный корень засчитывается как покрытие (трек E нашёл
39% BAD среди частых fallback-корней).

* `correctness[<выборка>]`: случайные пары «догадка → открытое слово» из
  отложенной выборки (цель — по частоте токена, догадка — по частоте леммы),
  стратифицированные по самому слабому звену связи (`kuznetsova`, `opaque`,
  `reviewed_row`, `nest_anchor`, `rule` — наречия и отрицания, `fallback`,
  `alias`, `proper`). Метки OK/BAD хранятся в
  `lexical/data/metrics/correctness_*.tsv`; OK значит, что игрок согласится:
  один школьный корень, сложное слово — только полной структурой. Точность по
  группам перевзвешивается долями групп в общий процент. **Цель: ≥95%.**
  Если чинить ровно размеченные BAD, эта выборка дальше завышает точность,
  поэтому честное текущее число даёт только свежая выборка
  (`metrics draw --per-group 30 --extra 100 --seed <новый>`, разметить,
  закоммитить). Новая выборка — раз в несколько пачек или после крупных
  изменений банка. Разметку делает агент, пограничные BAD стоит показать
  пользователю.
* `gold[bee]`: точность и полнота живого матчера по всем упорядоченным парам
  лемм статьи «Медоносная пчела» против ручной школьной разбивки
  `games/tests/censorly_testdata/articles/bee.roots.json`. Цифры не
  считаются, сложное слово ожидается только при совпадении всех корней. Это
  согласие со школьной нормой, а не точная правильность: эталон пропускает
  часть членов групп (обычно/обычный, связанный/связать) и расходится с
  сознательными решениями игры (смыслы «вести», ид/ход). Смотреть тренд и
  разбирать расхождения из `metrics gold --show 40`.

Первый замер 2026-11-09: `common` 93.9% / отложенная 93.1%, `all`
83.3% / 82.7%, `correctness` 92.7% (231 пара; kuznetsova 90% [74–97%],
fallback 87%, alias 90%, opaque, reviewed_row, nest_anchor, rule и proper
без BAD), `gold[bee]` точность 86.9%, полнота 46.6%.
Вторая выборка `s2` (265 пар, 144 из них в `kuznetsova`) дала 96.3%, у
`kuznetsova` 95.8% [91–98%]. Обе выборки вместе дают по Кузнецовой 9 BAD на
174 пары (~95%). Первая выборка из 30 пар оказалась неудачной. Ошибки
Кузнецовой рассеяны: почти все — родство только этимологическое (вплоть /
плотный, упрёк / поперёк, сколько / количество, пучить / пучок), по одной
паре на семью. Остальные BAD — омографы сокращений и имён (па, Света).

Хвост длинный. Топ-500 лемм-пропусков дают 28% токенов-пропусков, топ-1000 —
39%, топ-2000 — 50%, топ-5000 — 66%. Нужны решения на уровне семьи или
гнезда и массовые правила с ревью исключений.

## Как работать с роадмапом

1. Выбери трек. Если пользователь трек не назвал, бери верхний незакрытый по
   приоритету. Прочитай его раздел и последние строки **журнала**.
2. Сними метрику до изменений:
   `python -m games.puzzles.censorly.offline.tools.coverage_report`
   (строка `SUMMARY`).
3. Возьми пачку из очереди трека: 50–100 семей или лемм, по убыванию
   частоты в корпусе.
4. Каждую семью разбери **целиком** (все члены, не только пару из жалобы).
   Принятое пиши в файл решений трека. Отвергнутое пиши в файл отказов с
   причиной. Отказ — такая же ценная запись, как принятие: это память,
   которая не даёт следующему агенту повторить ту же ошибку.
5. Проверь представителей через `explain_pair` и прогони тесты Censorly.
6. Сними метрику после изменений и добавь строку в журнал (формат ниже).
   Обнови поле «Курсор» у трека.
7. Закоммить пачку одним коммитом: данные, тест-регрессия, строка журнала.

Не трогай `splits.py` в рамках треков покрытия. Ложные открытия и sense-сплиты
относятся к треку F и делаются по скиллу `censorly-root-family`.

## Треки

Приоритет определяется доля токенов, которые трек закрывает, делённая на
риск ложных открытий.

### W. Wiktionary как третий словарь (приоритет 1, инфраструктура)

**Почему.** Проба 2026-11-05 на выборках по 50 дыр из `coverage_report`
показала такую долю лемм с разбором `{{морфо-ru|…}}` на ru.wiktionary:

| Дыра | Есть `морфо-ru` |
|---|---:|
| `UNRESOLVED/opaque_single` (теорема, вероятность, помощь) | 50/50 |
| `UNRESOLVED/multi_component` (треугольник, равновесие, энтропия) | 46/50 |
| `UNRESOLVED/ambiguous_spelling` (связанный, допустимый) | 32/34 |
| `ABSENT/absent_common` (вид, роль, обычно, кулон) | 33/50 |
| `ABSENT/proper` (Гаусс, Николай, Селенга) | 8/50 |
| `ABSENT/unknown_word` (фотосистема, пластохинон) | 5/50 |

Почти у всех разборов стоит пометка `и=т`, то есть источник — словарь
Тихонова. Наш `RuMorphs-Lemmas.txt` (96k лемм) — неполная выгрузка Тихонова:
в нём нет даже «вид» и «роль». Wiktionary даёт нам более полного Тихонова и
поверх него ещё два слоя:

* `{{морфо-ru|по-|мощь|+∅}}` на каждой лемме. Формат: `x-` — приставка,
  голое `x` — корень, `-x` — суффикс, `-о-` — интерфикс, `+x` — окончание.
  Омонимы оформлены отдельными секциями (`вид I`, `вид II`), и у каждой свой
  разбор.
* **3 039 шаблонов `{{родств:<корень>}}`**. Это курируемые корневые гнёзда
  с алломорфами (`-вид⁽ʲ⁾-`) и членами по частям речи. Шаблон подключён на
  страницах членов гнезда. Гнёзда этимологические: в `родств:вид` попадают
  «завидный» и «ненавидеть». Поэтому гнездо — это **свидетельство**, а не
  готовая игровая семья.
* Секция «Родственные слова» на каждой странице: ближайшие родственники.
  Это высокоточный сигнал для пар.

Лицензия CC BY-SA 4.0. Извлечённые TSV коммитятся с указанием источника и
даты дампа в заголовке файла `*.meta.json`.

**Как встроить.** Wiktionary встраивается не как новый источник правды, а
как дополнительное свидетельство в существующем конвейере `rootbank`.

* **W1. Экстрактор (офлайн).** `offline/tools/wiktionary/extract.py` читает
  дамп `ruwiktionary-latest-pages-articles.xml.bz2` (~340 МБ, потоково, без
  распаковки на диск) и пишет:
  * `data/dictionaries/wiktionary_morphs.tsv`:
    `lemma  homonym  segmentation  source_flag`. Сегментация переводится в
    формат Тихонова (`по:PREF/мощь:ROOT/:END`), чтобы `_build_bank` разбирал
    её тем же кодом.
  * `data/dictionaries/wiktionary_families.tsv`:
    `template  root_alternants  lemma  pos  block`. Сюда же разворачиваются
    члены шаблонов `родств:*`.
  * `data/dictionaries/wiktionary_related.tsv`: `lemma  related  pos`.
  * Статистика: число лемм, сколько из них новых относительно Тихонова и
    Кузнецовой, сколько омонимов.
  Скачанный дамп класть в `var/wiktionary/` и читать с `python -I`
  (недоверенные данные). В git его не коммитить.
* **W2. Сегментация как резерв Тихонова (runtime).** В `_build_bank` лемма,
  которой нет в `RuMorphs-Lemmas.txt`, берёт части из `wiktionary_morphs.tsv`
  и проходит **тот же** `_authorize_component`: корень Кузнецовой по
  членству, `reviewed_opaque_roots` или уникальное написание. Новый
  `source` называется `WIKTIONARY_SEGMENT_*`, чтобы его было видно в
  provenance. Лемму с несколькими омонимичными разборами не авторизовать
  автоматически.
* **W3. Перекрёстная авторизация гнёздами.** Автоматическое
  `UNIQUE_SPELLING_FALLBACK` для Wiktionary-лемм разрешается только при
  подтверждении: лемма и хотя бы один член целевой семьи Кузнецовой стоят в
  одном шаблоне `родств:*`. Без подтверждения лемма уходит в очередь ревью.
* **W4. Гнёзда как генератор пачек для треков A–D.** Шаблон `родств:X`,
  у которого Тихонов-only корень и нет семьи Кузнецовой, сразу даёт
  кандидата в opaque с полным списком членов. Это лучшая очередь для трека A,
  чем однокорневые совпадения по написанию.
* **W5. Гнёзда как детектор ложных открытий (трек F).** Если семья
  Кузнецовой разложена Wiktionary по двум и более разным шаблонам
  `родств:*`, это кандидат на sense-сплит. Отчёт пишется в TSV для трека F.
* **W6. Проверка регрессий.** Golden-снимок банка (R1 из документа
  архитектуры) до и после W2/W3. Каждая новая структура должна иметь
  `source` `WIKTIONARY_*`. Изменение старых лемм недопустимо.

**Результаты W1 (2026-11-05, дамп `ruwiktionary-20261101`).**

* Извлечено 185k лемм с `морфо-ru` (из 469k русских страниц; остальные —
  словоформы или пустые шаблоны), 6.5k лемм с омонимами, 2 303 русских
  гнезда (125k членств), 440k связей «Родственные слова». Полный прогон
  занимает ~15 мин, а данные в `data/dictionaries/wiktionary_*` (~5 МБ gzip).
  Повторить так:
  `python -I games/puzzles/censorly/offline/tools/wiktionary/extract.py var/wiktionary/<dump>.xml.bz2 games/puzzles/censorly/lexical/data/dictionaries`,
  оценить:
  `python -m games.puzzles.censorly.offline.tools.wiktionary.compare --gaps-out /tmp/wk.tsv`.
* На общих леммах корни совпадают с Тихоновым в **98%** случаев
  (86.5k из 88.3k).
* **73.7k обычных лемм нет в нашем `RuMorphs-Lemmas.txt`**, а 69k нет в
  банке вообще.
* Сегментация сама по себе закрывает мало. Для 30.7k из 34.5k наших
  `UNRESOLVED` Wiktionary даёт **тот же** корень, что и Тихонов, поэтому
  проблема не в разборе, а в отсутствии решения по корню. Если симулировать
  авторизацию `rootbank` по 99k лемм-дыр, получается: `AUTO_CONFIRMED`
  (уникальное написание, подтверждённое общим гнездом) 5.5k,
  `UNIQUE_UNCONFIRMED` 11.5k, `REVIEW_AMBIGUOUS` 16.2k, `REVIEW_HOMONYMS`
  0.4k, `NEEDS_OPAQUE` 66.3k. На корпусе фикстур `AUTO_CONFIRMED` — это
  всего ~320 токенов (вид, быстро, видимый).
* **Самый ценный слой — гнёзда.** Для 38% корпусных токенов `NEEDS_OPAQUE`
  гнездо указывает на семью Кузнецовой: «обычно» ∈ `обык`, «значительно» ∈
  `знак`, «бесконечно» ∈ `конец`, «вероятность» ∈ `вер`. Тихоновский
  «opaque» корень на деле оказывается известной семьёй. Кроме того, гнёзда
  различают омонимичные корни (`пол I`/`пол II`/`пол III`, `генерал1`/`генерал2`).
* Нотация: `x--`/`--x` — префиксоид или суффиксоид. Маппится в ROOT, как у
  Тихонова (`фото:ROOT/синтез:ROOT`), иначе «фотосинтетический» совпал бы с
  «синтетическим».

**Пересмотренный порядок** (основная ценность переезжает из W2 в W4):

1. **W4 → треки A–D.** `compare --gaps-out` — это готовая очередь с
   вердиктом и гнёздами. Пачка — это гнездо целиком. Если члены гнезда в
   основном стоят в одной семье Кузнецовой, лемма-дыра получает
   `reviewed_existing_root_assignments.tsv` или `reviewed_derived_roots.tsv`
   на эту семью. Если у гнезда нет семьи Кузнецовой, это кандидат в opaque
   (трек A) с полным списком членов.
2. **W6 + W2.** Golden-снимок, затем runtime-резерв сегментации для ABSENT
   лемм. Автоматически применять только `AUTO_CONFIRMED` и `opaque`.
   `UNIQUE_UNCONFIRMED` (11.5k) без ревью не включать: это тот же риск,
   что у `UNIQUE_SPELLING_FALLBACK` (трек E).
3. **W5.** Семьи Кузнецовой, которые разложены по 2+ гнёздам, и
   омонимичные гнёзда (`X I`/`X II`) — это очередь для трека F.
4. **W3** сливается с W2: подтверждение по гнезду уже встроено в вердикт
   `compare`.

**W4: якоря гнёзд.** Новый runtime-слой `data/reviewed_nest_anchors.tsv`
(`lemma anchor nest note`). Лемма без корня получает **текущие** структуры
якоря вместе с sense. Если семью якоря потом переразобьют, якорная лемма
уйдёт вместе с ним. Источник `REVIEWED_NEST_ANCHOR`. Слой применяется после
отрицаний, а потом отрицания прогоняются ещё раз (`неверно` → `неверный`).
Своя корневая структура у леммы всегда сильнее якоря.

* Очередь: `python -m games.puzzles.censorly.offline.tools.wiktionary.nest_queue --output /tmp/nq.tsv`
  (`--all` выдаёт всё, не только корпус). Составные слова (2+ корня в
  Wiktionary) инструмент не якорит: «три» не должен открывать
  «треугольник», это трек C.
* Отказы: `data/rejected_nest_anchors.tsv` (`lemma anchor reason reviewed_at`).
  Пары оттуда инструмент больше не предлагает.
* Эвристика ревью: если якорь стоит в блоке «Родственные слова» самой леммы
  (`related=yes`), предложение почти всегда верное. Без этого часто мусор
  (сегодня → денёк, руководство → рукавичка). Всегда отвергать: фамилии
  (быков, сахаров), имена и реки (лена, сена), аббревиатуры, составные слова,
  лексикализованные слова (сейчас, сегодня, совершенно = «полностью»).
* Наречия в банк не попадают: у pymorphy это отдельные леммы, а в словарях
  Кузнецовой и Тихонова их нет. Но в живом матчинге большинство из них уже
  связано с семьёй через разбор pymorphy как краткой формы прилагательного
  («примерно» = кр. ф. «примерный»). Реальный остаток закрывает правило B2.

Курсор: W1 сделан. **W4 пачка 1** (2026-11-05): корпусная очередь,
+144 якоря, −68 отказов, +1 opaque (`вероят`), +3 отрицания.
**W4 пачка 2** (2026-11-09): `nest_queue --all`, `related=yes`, только
леммы из корпуса, которые остаются дырами в `coverage_report --gaps`
(644 штуки), топ-200 по `corpus_count`. Итог: +128 якорей, −70 отказов,
3 порядковых числительных и «мягкий»/«мягкость» через
`reviewed_existing_root_assignments`.

* Сортировать надо по корпусу, а не по `score`: `score` описывает
  качество пары, а не её вес. Пересечение с `--gaps` обязательно, иначе
  в очередь попадают наречия, которые живой матчер уже связал через `ADJS`.
* `related=yes` не спасает от разных смыслов одного гнезда: актуальный и
  актёр, текстура и текст, радиация и радиус, комбинат и комбинаторика,
  угорский и гора, ленный и ленивый. Из 200 отвергнуто 70, в основном
  фамилии, имена, топонимы и составные.
* Якорь на `шестнадцать` не работает: корни `root:numeral_N` назначаются
  после прохода якорей. Порядковые числительные надо писать в
  `reviewed_existing_root_assignments.tsv`, как «двенадцатый».
* Хвосты: «идеал»/«идеальный» нужна своя семья (трек A, `идея` её не
  покрывает); «напольный» ждёт sense «пол = floor» (трек F); у «неведомый»
  якорь смешивает смыслы know и administration.

Следующая пачка: остаток той же очереди, ранги 201–644 (~750 токенов,
длинный хвост). Дальше выгоднее вернуться к треку A.

### C0. Корпус для приоритизации (приоритет 1, инфраструктура)

Фикстуры — это 29 статей с естественнонаучным перекосом, и `corpus_frequency`
в майнере почти везде 0–2. Нужен снимок `data/corpus_lemma_freq.tsv`
(лемма → число токенов) по 300–1000 статьям из `article_pool.txt` или из
сохранённых payload ежедневных выпусков. Используют его `coverage_report` и
`candidate_miner`; тексты статей в git не кладутся, только частоты.

**Сделано 2026-11-06.** `offline/tools/corpus/build_corpus.py` берёт

Приёмы, которые понадобились в A1:
* **Своя `root:` метка через `reviewed_derived`**, когда корень Тихонова

  написанию с Кузнецовой (`тем` = тема / тёмный / темя). Пример:
  `root:organize` и отдельный `root:organism`.
* **Перенос в существующий корень**, когда Тихонов пишет корень по-разному
  (министр / министер, минерал / минераль, детермин / де+термин): лемма
  получает `tikh:<основной корень>` через `reviewed_derived`.
* Базовое слово вне Тихонова, у которого семья уже стала opaque (мотив,
  тюрк), тоже получает `reviewed_derived`.
* Побочный эффект: явное назначение стоит в банке раньше
  `UNIQUE_SPELLING_FALLBACK` и убирает его ложные открытия.
  Пример: «стилистика» больше не открывает «стол».

#### B2. Правило «наречие → прилагательное» (2026-11-06)

Генератор `offline/tools/adverb_rule.py` пишет `data/adverb_bases.tsv`
(`adverb adjective evidence`). Runtime копирует структуры прилагательного
на проходе якорей (источник `ADVERB_OF_ADJECTIVE`), ручные якоря сильнее
правила. Улики три: краткая форма среднего рода по pymorphy, «-ски» →
«-ский», «по-…ому» → прилагательное.

* Строка пишется, только если runtime не связывает наречие с семьёй иначе
  (через разбор `ADJS` или дефисную структуру). Из 1 875 пар наречий с
  прилагательным 1 573 уже были покрыты. Остаток — 302 строки: 276 «-ски»
  (фактически, экономически, политически), 24 «по-…ому», 2 прочих.
* Исключения с причинами: `data/adverb_rule_exceptions.tsv` (конечно,
  здорово, именно, довольно, собственно, совершенно, видимо…).
* Эффект на корпусе: +639 токенов. Гипотеза «наречия — большая дыра»
  оказалась артефактом метрики, которая смотрела только в банк.
* **Ограничение:** исключения не мешают открытиям через разбор `ADJS`.
  «совершить → совершенно» и «видеть → видимо» открыты разбором pymorphy,
  а не правилом. Закрыть такие пары можно только через
  `reading_overrides` (трек F).
* Пересобирать после крупных изменений корней:
  `python -m games.puzzles.censorly.offline.tools.adverb_rule --review /tmp/adv.tsv`.

### C. Составные без корня (приоритет 3)

`UNRESOLVED/multi_component`: 14.7k лемм в банке (треугольник = тр+уголь,
атмосфера = атмо+сфер, взаимодействие = взаим+дей). Обычно один компонент не
авторизуется (`тр` — два корня Кузнецовой, `атмо` нет нигде). Решения:
`reviewed_derived_roots.tsv` с полной структурой (`fam:три+fam:угол`) или
opaque для связанной формы (`сфер`). Правило игры сохраняется: сложное
слово открывается только полной структурой. «Угол» не открывает
«треугольник», а «прямоугольный» с «треугольником» не открывается.

Очередь: `python -m games.puzzles.censorly.offline.tools.compound_queue
--count 150 --tsv /tmp/compounds.tsv`. Тул группирует неразрешённые составные
по набору корней Тихонова (самолёт и самолётный — одна семья `сам+лет`),
ранжирует по корпусу и для каждого компонента показывает игровые корни
однокоренных слов. `proposal` — только подсказка: для «столетие» он
предлагает `лет²` (полёт), а нужно `лет¹` (лета).

Два вида решений:
* **Русское составное** — полная структура из корней компонентов
  (`fam:лет¹+fam:сот¹|ст`). Открывается только своей семьёй.
* **Международная лексикализованная семья** (-логия, -граф, теле-, атмо-) —
  свой `root:` id на всю семью, как `root:psychology`: экология ↔
  экологический, телевидение ↔ телевизор, но не «логика → экология».
  Связанные формы (теле, гео, лог, граф) глобально не авторизуются.

Курсор: **пачка D1** (2026-11-09) — ~90 строк `ambiguous_spelling`, остаток

### E. Аудит `UNIQUE_SPELLING_FALLBACK` (приоритет 4, риск ложных открытий)

9 515 лемм получили корень без ревью, только по совпадению написания. Это
скрытый источник ложных открытий. План: выборка по 100 лемм с самой высокой
частотой, ручная разметка OK/BAD. Если доля BAD больше 5%, нужен механизм
`rejected_fallback.tsv` в runtime (сейчас его нет). После W1 можно
автоматически подтверждать пары по общему шаблону `родств:*`.

Очередь: `python -m games.puzzles.censorly.offline.tools.fallback_audit
--count 150 --tsv /tmp/e.tsv` (~1 мин). Группы «морф → корень» по убыванию
корпуса, рядом — семья, к которой прилипли леммы. Поле `nest` (общее гнездо
Wiktionary) **не подтверждает** совпадение: в топ-200 9 из 28 групп с
ошибкой «подтверждены» им. Размечать вручную.

**Пачка E1** (2026-11-09). Ручная разметка топ-100 лемм: **39 BAD** (вена →
венок, турист → турить, раса → расти, логика → положить, комедия → ком,
армянин → армия). Порог 5% превышен, поэтому появился runtime-файл
`data/rejected_fallback.tsv` (`morph root reason reviewed_at`): отвергнутая
пара оставляет компонент неавторизованным в `_authorize_component`, лемма
остаётся без корня. Правило работы:
* группа почти целиком ошибочна → строка в `rejected_fallback.tsv` и
  правильные корни частым леммам через `reviewed_derived` (`root:race`,
  `root:tourism`, `root:logic`…);
* группа смешанная (вест/известие, торий/торить, миля/милый) → только
  `reviewed_derived` для ошибочных лемм, отказ не пишется;
* ошибка в самой семье Кузнецовой (хор ↔ хорь, бред ↔ бродить) — это не
  трек E, а трек F.

E1: 23 отказа, 100 лемм с правильными корнями, «армянин» в кластере Армении.
Метрика не изменилась (83.7%), `unique_spelling_fallback` 9498 → 9224.
**Пачка E2** (2026-11-09) — группы ~175–420 (по 4–14 токенов): 13 отказов
(сон → диссонанс, ют, сап, тут, рун, нон, гам, миш, тат…), 32 леммы с верным
корнем (спора, прибалтийский, тир, нарвал, родий, гербарий, флотация).
Составные почти все верные. Ошибки сосредоточены в заимствованиях и
экзотизмах, которые совпали с коротким русским корнем. Метрика 83.7% → 83.6%,
`unique_spelling_fallback` 9224 → 9148.
Курсор: разобрано до ~420-й группы (`t≥4`). Дальше группы по 1–3 токена:
отдача низкая, разумнее ловить ошибки по жалобам через `explain_pair`.


### P. Имена собственные → прилагательные (приоритет 4)

«Тибет» ↔ «тибетский», «Казань» ↔ «казанский», «Монголия» ↔ «монгольский».
Сейчас это закрыто. Решение: кластеры в `match/proper_names.py`. Очередь:
пары «Geox-лемма pymorphy + прилагательное на -ский с тем же основанием»,
отфильтрованные по корпусу. Wiktionary здесь помогает слабо (16% покрытия),
лучше брать данные из Wikidata (есть `wikidata_candidates`).

Очередь: `python -m games.puzzles.censorly.offline.tools.proper_queue
--count 250 --tsv /tmp/proper.tsv` (~5 мин). Тул ищет пары «имя собственное
корпуса ↔ прилагательное на -ский/-цкий или житель» с общим длинным
префиксом, которые живой матчер не открывает. Шумный: «франция → франциска»,
«балкан → балканский» (уже связано через `tikh:балкан`), поэтому каждую
семью проверяй через `explain_pair`.

Два механизма:
* **Кластер** `('sense:X', (…))` в `CLUSTERS`: все члены получают
  `root:proper_X`. Это корень в банке, он двигает метрику.
* **Пара** в `PAIR_RELATIONS`: связь на уровне матча, метрику не меняет.
  Слово из пары нельзя класть в кластер (тест
  `test_new_pairs_are_not_accidentally_clustered`), поэтому семьи, где уже
  есть пары Wikidata-демонимов (Греция, Швейцария, Литва, Ирландия, Венеция),
  дополняются парами. При добавлении пар обнови счётчик в
  `test_confirmed_proper_pairs_are_bidirectional`.

Не включать демонимы-омонимы: шотландка (ткань), чешка (обувь), голландка
(печь), литовка (коса), венгерка (куртка). Решения пользователя (2026-11-09): «Нобель → нобелевский» открыт (пара),
«греча → греческий» закрыт: гречишные слова получили `root:buckwheat`.

Курсор: **пачка P1** (2026-11-09) — 66 новых кластеров (Византия, Голландия,
Персия, Пруссия, Македония, Португалия по паре, Кельн, Урал, Пермь, Мюнхен,
Шекспир, Эйнштейн…), 8 расширено жителями (австралиец, мексиканец, поляк,
турок), 27 новых пар. Остаток `ABSENT/proper` — это в основном личные имена
(Александр, Генрих, Джон) и аббревиатуры (США, СССР): у них нет семьи, это
не трек P.


#### P2. Организации и учебные заведения

Офлайн-сборщик `candidates.proper_candidates` выделяет `organizations` и
`educational_institutions` отдельно от `brands`. При запуске с Wiktextract
JSONL он пишет `organization_adjectives.tsv`: кандидаты со связью с
прилагательным на `-ский`/`-цкий`/`-жский` и источником, отмеченным как
организация или учебное заведение. Поле `review_status=manual_review` означает,
что даже кандидат с высокой уверенностью не подключается к игре автоматически.
Пример запуска из корня репозитория:

```bash
../venv/interoves_django/bin/python -m games.puzzles.censorly.offline.tools.candidates.proper_candidates \
  --input /path/to/ruwiktextract.jsonl.gz \
  --organization-tsv /tmp/organization_adjectives.tsv
```

Перед внесением пары в `match/proper_names.py` проверять значение названия,
омонимию, падежные формы и весь связный компонент существующих proper-пар.
Связи из поля Wiktextract `related` попадают в очередь только при близком
написании основы и требуют отдельного подтверждения: само поле не доказывает
словообразование. Бренды остаются отдельным направлением ревью.

Пробная очередь от 2026-11-08 сохранена в
`artifacts/analytics/2026-11/censorly-organization-adjectives-2026-11-08.tsv`:
14 пар (7 организаций из Wiktextract и 7 учебных заведений из названий
статей пула). До принятия все 14 давали CLOSED; пользователь подтвердил
их 2026-11-08, и они добавлены в `proper_names.py`. Для «ВОЗ» добавлена
проверка регистра, чтобы нарицательное «воз» не открывало «возовский».
«Йель → йельский» уже давал OPEN и в эту очередь не вошёл.
