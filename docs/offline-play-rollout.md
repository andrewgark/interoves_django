## Что уходит в релиз

Код спит, пока не включён флаг и не создано правило. Поведение сайта после
деплоя не меняется, кроме двух мест:

- на **турнирной** Лесенке в разметке больше нет нерешённых слов
  (`data-prev-word`/`data-next-word` у подсказок);
- обычные отправки Лесенки несут `client_event_id`, поэтому после abort/таймаута
  страница повторяет их сама (сервер отвечает исходным ходом, дубля нет).

Миграции (все расширяющие, проверено `apply_release_migrations` на MySQL 8 —
«Plan is safe to apply before switching code»):

| Миграция | Что делает |
|---|---|
| `0295_client_event_receipt` | новая таблица `ClientEventReceipt` |
| `0296_offline_play_rule` | новая таблица `OfflinePlayRule` + check constraint на ней |
| `0297_timing_event_credit_cap` | `ALTER TABLE games_dailytimingevent ADD COLUMN credit_cap_ms bigint NULL` (instant на MySQL 8) |

Проверки на MySQL 8 (одноразовый контейнер): 75 тестов офлайн-режима, повторной
отправки, Лесенки, таймера и телеметрии; гонка четырёх одновременных повторов
одного `client_event_id` (`test_client_event_receipts_mysql`) даёт одну
попытку и одну квитанцию.

Статика на проде отдаётся с того же домена (`https://interoves.com/static/releases/<id>/`
через nginx), поэтому Service Worker кэширует её; `/offline-sw.js` отдаёт Django.

## Деплой

Обычный `deploy_green` — миграции пройдут автоматически. Переменных окружения
для самого деплоя не нужно.

## Включение (по шагам)

1. **Флаг.** `OFFLINE_PLAY_ENABLED=true` в окружении web (`eb setenv` или
   `.ebextensions/django.config`). Без правил он ничего не меняет.
2. **Мгновенный вердикт, 5%.** Админка → *Offline play rules* → правило:
   игра `ladder`, тип `raddle`, режим `general`, ✔ «instant verdict»,
   доля игроков `5`. Сохранение сбрасывает кэш правил (Redis общий).
3. **Наблюдать ~сутки**, затем 50% → 100%:
   - лог `offline_verdict_divergence` — ожидается **0**; любой случай
     приходит алертом `offline_play` в Telegram (не чаще раза в час на
     задание) — это баг нормализации/спеки, разбирать до расширения;
   - `offline_pack_build_failed` — сломанные `checker_data` задания.
4. **Офлайн-ходы, 5%** — в том же правиле ✔ «offline attempts». Смотреть:
   - секцию «Офлайн-режим» в дневном отчёте админу (`queue_synced`,
     `pack_failed`, `sw_failed`, `assemble_failed`, …);
   - алерты `assemble_failed` / `restore_failed` / `queue_dropped` (баги);
   - нагрузку `POST /raddle_offline_pack/<id>/`: один запрос на загрузку
     страницы Лесенки у игрока с возможностью; ~50 мс CPU для 12 слов
     (до ~0,6 с для 50), ~7 КБ gzip.
   Затем 50% → 100%.
5. **Офлайн-время** — ✔ «offline timing». Смотреть лог
   `daily_timing_offline_credit` и счётчик «Засчитано время офлайн-игры»;
   у таких строк растёт `client_credited_ms` (видно в админке таймингов).

Запросы для CloudWatch Logs Insights:

```
fields @timestamp, @message
| filter @message like /offline_verdict_divergence|offline_pack_build_failed|offline_client_event|daily_timing_offline_credit/
| sort @timestamp desc
```

## Откат

- **Точечно:** снять галочку или выключить правило — новые пакеты/спеки
  перестают выдаваться сразу; уже начатые офлайн-ходы всё равно дойдут
  (это обычные `/send_attempt/`).
- **Полностью:** `OFFLINE_PLAY_ENABLED=false`. `/offline-sw.js` начинает
  отдавать воркер, который удаляет свои кэши и снимает регистрацию при
  следующей проверке обновления браузером; страницы перестают получать спеку и
  пакет; очереди, оставшиеся в браузерах, по-прежнему отправляются.
- Миграции откатывать не нужно: новые таблицы/колонка не используются без
  флага.

## Известные ограничения

- Офлайн играется только страница, загруженная онлайн хотя бы раз (её пакет и
  копия в кэше SW); без сети открывается лишь «запомненная» страница.
- Время, накопленное до перезагрузки без сети, теряется (живёт в памяти
  таймера).
- Подсказки-ассисты без сети недоступны; взятая онлайн подсказка
  перезапрашивает пакет.
- Лайки подсказок, черновики и пометки в кусочках пакета застывают на момент
  его загрузки (черновики и пометки страница восстанавливает сама).
- Командная игра — всегда онлайн.
