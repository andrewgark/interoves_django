# Production smoke для командного таймера

Для безопасной проверки параллельных вкладок создан отдельный production actor:

- username: `daily_timing_smoke`;
- team: `daily_timing_smoke_team`;
- `Profile.is_hidden = true`;
- `Team.is_hidden = true`;
- `Team.is_tester = true`;
- аккаунт создан с unusable password, пока credentials не заведены в защищённом окружении.

Эти объекты нельзя использовать для обычной игры, публичных результатов или
ручных пользовательских сценариев. Smoke должен работать только с ними и с
отдельной тестовой игрой/выпуском.

## Что проверять

Две независимые browser-сессии открывают один командный выпуск:

1. обе сессии отправляют `start` с разными `session_id`;
2. первая отправляет `pause`;
3. вторая продолжает отправлять heartbeat;
4. пересекающийся интервал считается один раз;
5. завершение фиксирует итоговое время без блокировки второй сессии.

Ожидаемая семантика:

- пауза одной вкладки локальна;
- командный timer считает объединение активных интервалов;
- повторная вкладка одного личного пользователя не удваивает время, а
  передаёт active lease новой сессии.

## Credentials

Пароль не хранится в репозитории и не выводится в логи. Перед live-smoke его
нужно задать через согласованный secret/CI secret и передать smoke-скрипту через
`DAILY_TIMING_SMOKE_PASSWORD`. Username и team name можно брать из этого файла.

Не запускайте обычный Django `manage.py test` против production: тестовый класс
создаёт и удаляет тестовую БД. Для production используется отдельный live-smoke
с реальными HTTP/browser-сессиями и только этим скрытым actor.
