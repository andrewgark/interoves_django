# Цензурки: алгоритм матчинга слов

Снимок от 2026-11-10, после рефакторинга по
[censorly-matching-refactor-plan.md](censorly-matching-refactor-plan.md).
В коде одна реализация матчинга: `games/puzzles/censorly/lexical/`. Где
чинить конкретную жалобу, написано в
[agents/censorly-matching.md](../agents/censorly-matching.md).

Цифры получены через `rootbank.provenance()` и замер слоёв на 8 000 самых
частых лемм корпуса. Если код изменился, пересчитай их (§8).

---

## 0. Картинка целиком

```
                 СТАТЬЯ                                   ДОГАДКА
                    │                                        │
          text/tokenize.py                                   │
  kind=content|stop, лемма pymorphy,                         │
  маркер TokenContext для омографов                          │
                    │                                        │
         ANALYZER.target(surface, lemma)          ANALYZER.guess(surface)*
                    │  READINGS · VISIBILITY · ROOT_BANK     │
                    ▼                                        ▼
                  Word ──────────────┐            ┌────── Word
                                     ▼            ▼
                     ArticleIndex: постинги по ключам слоёв
                                     │
                            candidate_ids(guess)
                                     │
                        MATCHER.relation(guess, word)   ← §5
                                     │
                  непустой ответ → сохранённая лемма токена открыта
```

\* Статья уточняет чтение догадки (`index.guess_words`): если написание
встречается в статье ровно с одной леммой, догадка берёт её («Граната» в
статье о гранате — гранат); если в статье есть метка-омограф («порт.» перед
переводом), догадка «порт» читается ещё и как «португальский». Без метки
«порт», «кит», «нем» — обычные слова.

Открытие экзистенциальное: достаточно одной согласованной пары чтений.
Открывается не токен, а **сохранённая лемма** токена: открыв одну форму,
игрок открывает все токены с той же леммой.

## 1. Термины

| Термин | Что это | Пример |
|---|---|---|
| **fold** | NFC, без ударений, casefold, ё→е | `Ёлки` → `елки` |
| **чтение** (`Reading`) | разбор pymorphy: лемма, парадигма, POS, score, «это имя» | `стали` → сталь, стать |
| **лексема** | `(para_id, lemma)`: одна парадигма | все формы «улей» |
| **root id** | `fam:<семья Кузнецовой>`, `tikh:<морф>`, `root:<ручной>` | `fam:мен¹` |
| **sense** | `sense:<кластер>`: метка смысла, корнем не бывает | `sense:weather` |
| **структура** | отсортированный кортеж root id + sense, сравнивается целиком | `('fam:бел', 'fam:снег')` |
| **семья** | семья Кузнецовой до игровых сплитов; только для отчёта near-miss | `мен¹` |
| **service** | слово открыто с начала игры | «и», «он», «5» |
| **контекст** | маркер `__censorly_*__` в лемме токена | «г.» после года |

## 2. Сущности

Четыре вида объектов, у каждого одно назначение.

### 2A. Внешние словари — `lexical/sources/`, класс `ExternalDictionary`

Загружаются лениво, один раз на процесс; после сборки банка сырые данные
освобождаются (`release()`).

| Объект | Файл | Отвечает на вопрос |
|---|---|---|
| `MORPHOLOGY` (`Morphology`) | pymorphy3 | какие разборы у написания. Единственное место, где вызывается анализатор |
| `KUZNETSOVA` (`Kuznetsova`) | `dictionaries/lemmas_to_roots.tsv`, `root_groups.txt` | корни леммы, семья корня, корни данного написания |
| `TIKHONOV` (`Tikhonov`) | `dictionaries/RuMorphs-Lemmas.txt` | морфы-корни леммы |

Wiktionary (`dictionaries/wiktionary_*`) читают только офлайн-тулы.

### 2B. Наши словари — `lexical/reviewed/`, класс `ReviewedTable`

Все таблицы, которые читает игра, перечислены в `reviewed/__init__.py`.
Каждая знает свой файл, точный заголовок и проверки; битая строка падает
при импорте. Остальные TSV в `data/` — очереди ревью и отчёты, на игру не
влияют.

| Вопрос | Таблицы |
|---|---|
| виден ли токен с начала | `visibility.tsv` (never_open / always_open / pronoun_adjective) |
| какие чтения у написания | `rejected_readings.tsv`, `target_readings.tsv` (filter / substitute / closed), `fixed_readings.tsv` (лет → год, Троя), `labels.tsv` (фр → французский, юго → юг, кит. в позиции метки) |
| какие корни у леммы | `reviewed_derived_roots.tsv`, `reviewed_existing_root_assignments.tsv`, `reviewed_opaque_roots.tsv`, `rejected_fallback.tsv`, `digit_cardinals.tsv` |
| у леммы корни другой леммы (`AnchorTable`) | `negation_pairs.tsv`, `reviewed_nest_anchors.tsv`, `adverb_bases.tsv`, `half_compounds.tsv` |
| прямые связи пар | `aliases.tsv`, `grammar_groups.tsv` |

Ещё код, а не таблицы: sense-кластеры в `splits.py` и имена собственные в
`match/proper_names.py` (план, Ш9). `lexical/senses.py` собирает их в один
словарь `SENSES`.

### 2C. Контекст статьи — `lexical/context.py`, класс `TokenContext`

Токенизатор решает, **где** применить контекст, и пишет маркер в лемму
токена. `TokenContext` говорит, **что** он значит:

| Поле | Смысл | Пример |
|---|---|---|
| `lemmas` | токен читается как эти леммы | «г.» после года → год |
| `readings` | без `lemmas`: какие чтения оставить | «нем» вне оборота → нем, немой |
| `closed` | скрыт с начала, хоть и служебное написание | «том» как книга |
| `exact_opens` | открывается ли своим написанием | «в.» (век) — нет, только «век» |
| `expands_guess` | в статье с таким токеном догадка тем же написанием читается и как `lemmas` | «порт.» → португальский |
| `guess_lemmas` | открывают только такие догадки; пусто = только написание | «о нём» — он/оно; инициал «Д.» — «д» |

### 2D. Решатели — `lexical/deciders/`

| Объект | Вопрос |
|---|---|
| `READINGS` (`ReadingSelector`) | какие чтения верить: `all`, `for_guess` (начальная форма первой), `for_target` (существительное первым), правки из таблиц |
| `VISIBILITY` (`Visibility`) | открыто ли слово с начала |
| `ROOT_BANK` (`RootBank`) | лемма → структуры, провенанс (§4) |
| `ANALYZER` (`WordAnalyzer`) | написание + контекст → `Word` (§3) |
| слои (`layers.py`) | связаны ли два `Word` одним способом; у каждого слоя и предикат, и ключи индекса |
| `MATCHER` (`Matcher`) | порядок слоёв и шлюзы (§5) |
| `ArticleIndex` | слова статьи, постинги, кандидаты; `analyze_guess` |

Точки входа для игры, тулов и тестов: `lexical.match`
(`analyze_guess`, `matching_lemmas`, `same_word`, `ANALYZER`, `MATCHER`),
`lexical.match.rootbank` (`structures_of`, `assignment_of`, `provenance`),
`lexical.semantics` (`explain`, `opens` — то же, что игра, для пары слов).

## 3. `WordAnalyzer`: из написания в `Word`

Догадка и токен статьи проходят один анализ. Различия собраны в таблице в
докстринге `deciders/analyzer.py`:

| | догадка | токен статьи |
|---|---|---|
| чтения | `for_guess` | `for_target` |
| чтения для корней | те же | `for_guess` написания |
| фиксированная лемма | лет → год, Троя | только заглавная (Троя) |
| контекст | если статья однозначна | своя лемма токена |
| видимость | `initially_open` | ещё и `closed` контекста/таблицы |
| обратная лексема | `lexemes_by_fold` | — |

Структуры написания (`ANALYZER.structures`): структуры самого написания,
его метки (фр → французский), лемм его чтений, проверенной леммы среди
предсказанных разборов, а для слова через дефис — все комбинации частей
(не больше 32).

## 4. `RootBank`: лемма → структуры

Строится один раз на процесс (~4 с). 76 460 лемм.

```
лемма
├─① есть в SENSES (splits.py, proper_names.py)?
│     корень: SEMANTIC_ROOT_ASSIGNMENTS, иначе Тихонов-составное, иначе
│     Кузнецова, иначе один морф; к каждой структуре дописывается sense
│                                               ─► SEMANTIC_SPLIT_ROOTED      24 073
│                                               ─► SEMANTIC_ROOT_ASSIGNMENT      685
├─② reviewed_derived_roots.tsv                 ─► REVIEWED_DERIVED_ROOT       2 156
├─③ reviewed_existing_root_assignments.tsv     ─► REVIEWED_EXISTING_ROOT         48
├─④ Тихонов ≥2 морфа: каждый через authorize; любой неавторизованный →
│     вся лемма UNRESOLVED, >32 комбинаций → TOO_AMBIGUOUS
├─⑤ Кузнецова                                  ─► KUZNETSOVA(_MULTI)      30 916
└─⑥ один морф Тихонова → authorize             ─► REVIEWED_OPAQUE_ROOT     5 763
                                                ─► UNIQUE_SPELLING_FALLBACK 9 148
                                                ─► UNRESOLVED              31 257
```

`authorize(морф)`: корни Кузнецовой самой леммы выбирают среди кандидатов
того же написания; без них — проверенный opaque-корень `tikh:*`, иначе
единственный кандидат, если пары нет в `rejected_fallback.tsv`, иначе ничего.

Потом таблицы-якоря копируют структуры, по порядку `anchor_passes()`:
отрицания (`bare_subset`), якоря гнёзд и наречия (`rootless`, цепочки до 3),
отрицания ещё раз (`rootless`), «пол-» (`always`). Последними цифры берут
структуры своих числительных.

## 5. `Matcher.relation`: дерево решения

```
relation(guess, target)
│
├─ пустой fold                                       → закрыто
├─ одно написание
│     оба открыты с начала или контекст не открывается
│     своим написанием («в.» век)                    → закрыто, иначе exact
├─ шлюз служебного слова: открытая догадка без смысла
│     (не местоимение и не 0–9)                      → закрыто
├─ шлюз контекста: target принимает только guess_lemmas
│     («о нём» ← он/оно; инициал ← только буква)     → lexeme или закрыто
├─ alias (кг/килограмм в любом падеже, 10/X)         → alias
├─ шлюз цифр: цифра открывает только своё числительное → закрыто
├─ одна сторона открыта с начала:
│     общая лексема → lexeme; общая структура и местоимение → root;
│     грамматика с числительным 2–9 → grammar; иначе закрыто
├─ proper (компоненты имён; строчное слово — не имя) → proper
├─ шлюз «не русское»                                 → закрыто
└─ lexeme → обратная лексема → root → grammar        → первый сработавший
```

### Слои и индекс

Каждый слой (`layers.py`) — объект с `opens(g, t)` и ключами
`guess_keys`/`target_keys`. `ArticleIndex` строит постинги только по
`target_keys`, а `Matcher.guess_layers` выбирает слои догадки по тем же
шлюзам. Поэтому индекс не может пропустить пару, которую открыл бы слой:
тест `IndexAgreesWithMatcherTests` перебирает все пары нескольких статей.

| Слой | Связь | Ключ |
|---|---|---|
| `EXACT` | одно написание | fold |
| `ALIAS` | сокращение ↔ полная форма (полная — по лемме, сокращение — по написанию) | группа |
| `PROPER` | компонента связей имён (`PAIR_RELATIONS`) | компонента |
| `LEXEME` | общая `(para_id, lemma)` | лексема |
| `REVERSE_LEXEME` | токен — начальная форма другого чтения догадки | лексема (постинги `LEXEME`) |
| `ROOT` | общая структура целиком | структура |
| `GRAMMAR` | супплетивы и порядковые (два/второй) | группа |

### Сколько срабатывает каждый слой

Замер 2026-11-09: 8 000 частых лемм корпуса, 4 000 догадок по их формам,
все кандидаты с другой леммой.

| Слой | Открытий |
|---|---:|
| `root` | 10 771 (95%) |
| `lexeme` | 370 |
| `proper` | 104 |
| `alias` | 40 |
| `grammar` | 1 |

## 7. Как проверить изменение

```bash
python -m games.puzzles.censorly.offline.tools.matching_snapshot --out /tmp/snap
```

Пишет `bank.tsv` (лемма → структуры, источник) и `decisions.tsv` (29
фикстурных статей × все их словоформы + ~100 трудных догадок → открытые
леммы, слой, near-miss). Сними до и после правки и сравни `diff`:
изменились ровно те строки, которые ты хотел изменить.

## 8. Как пересчитать цифры

```python
from collections import Counter
from games.puzzles.censorly.lexical.match import rootbank
Counter(v['source'] for v in rootbank.provenance().values())   # §4
```

Слои (§5): построить `ArticleIndex` по топу
`offline.corpus._from_file()` (лемма, `top_surface`) и посчитать
`MATCHER.relation` для `candidate_ids(..., include_near_misses=False)`.
